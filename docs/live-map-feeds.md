# Air, sea and weather map layers

The map polls `/api/live-context` while its page is active and the browser is visible. Aircraft and vessels are on by default. Weather uses an independent `/api/current-weather` request for Malé conditions; it does not wait for aircraft, AIS or a regional forecast grid. Positions remain at their reported coordinates between updates, without simulated movement. Timetable playback stays separate from observed traffic.

The Weather sidebar has a current-conditions section and explicit rain, flood and wind tests. There is no wind, wave or rainfall canvas overlay. Regional icons appear below zoom 10; local impacts use the existing island hexagons and roads above zoom 10, preserving the selected basemap.

The current Malé card distinguishes an airport observation from its explicitly labeled model fallback. The airport is near Malé, and one station does not measure weather across every island or the surrounding sea. Regional weather-model samples are neither live radar nor station measurements. Regional wave models have limited coastal detail. These feeds provide context and do not automatically alter bus/ferry routing, close roads, predict congestion, or establish an international voyage.

`CurrentWeatherConditions` includes `kind` (`observation`, `model` or `null`), source, retrieval time, observation/model valid time, station identity and coordinates, condition text, temperature, wind, optional precipitation interval and the original public METAR report. An unavailable server response has no measurement values. The sidebar may retain a previously received report only while it is still fresh, with its original time and a failed-refresh message; expired reports disappear. A successful model fallback never inherits the station identity. All clients share the server cache and concurrent current requests coalesce.

## Weather interpretation and impact scenarios

Current Malé conditions are a fresh airport observation or an explicitly labeled model fallback. The map uses the same current report for the Malé icon; other regional icons are current-hour model samples. Expired records disappear instead of being displayed as live. The current report follows the real clock, while transport scenarios use the explicitly shown planning date and departure time. Weather reports can flag exposure but never generate confirmed closures. Wind speed is in knots and wind direction is where it comes from.

- **Current:** local yellow cells flag rain/wind exposure near valid reports. No routing restrictions are inferred; calm or unavailable conditions do not create a hazard.
- **Heavy rain:** an explicitly assumed 1.25 moving-time multiplier on legal driving roads in the selected planning island. A grouped disruption computes distance-scaled incremental bus time, rather than assigning an arbitrary delay to every tiny road segment.
- **Flooded roads:** the user selects road segments. Only those roads are closed to buses and pedestrians, in both permitted directions, for the planning day. Nearby cells turn red; calculated downstream access losses and slower journeys also change cells.
- **Strong wind:** assumed exposure is shown first. Selected roads or bridges can be explicitly closed as a scenario. Vessel cancellation or sailing safety is not inferred.

Weather-generated disruptions have a reserved `weather-impact:` ID prefix and assumed provenance. Switching scenarios replaces only these disruptions. Existing proposal actions and other disruptions remain in place; undo and saved proposals retain valid grouped events.

Journey impacts compare the latest scenario against a separately calculated reference containing the same proposal and non-weather assumptions, with only weather-generated disruptions removed. Comparisons are shown only for matching completed analyses. Unknown journeys remain unknown, and average extra minutes are population weighted among comparable reachable journeys. Cells are display allocations of population; they are not measured flood depths or observations of inundation.

The unused `/api/weather-field` backend remains available for future forecast analysis but the map Weather flow does not request or render it. It retains its documented coarse model spacing and cache/source limitations.

## Interface decisions

| Before                                   | After                                                                 | Why                                                                                                                    |
| ---------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Historical port and airport context only | A compact air-and-sea pill with source status and observation details | Users can distinguish current positions from published statistics.                                                     |
| Greater Malé planning extent             | Explicit Maldives overview and return-to-planning action              | Wider traffic is inspectable without replacing the local policy workflow.                                              |
| Uniform vessel symbols                   | Four reported-length bands and a neutral unknown-size marker          | Makes scale legible without inventing dimensions. Symbols are enlarged for readability, not drawn to geographic scale. |
| Continuous weather canvas                | Regional icons and island-scale impact colors                         | Keeps the underlying geography readable and prioritizes consequences.                                                  |
| Display settings and forecast dock       | Current conditions with three explicit transport tests                | Makes real conditions and scenario assumptions distinct.                                                               |
| Weather disconnected from routing        | Distance-scaled rain delay and user-selected road closures            | Supports useful journey/access comparisons without inventing incidents.                                                |
| Cumulative proposal impact               | A matching proposal without the weather test                          | Isolates the weather effect from earlier edits.                                                                        |
| Local opening with unrestricted zoom-out | A skippable globe-to-Malé flight and responsive Maldives zoom floor   | Establishes place while keeping exploration focused on the country.                                                    |

The opening uses the existing EOX 2025 satellite mosaic, with its attribution and noncommercial licence. Reduced motion skips the animation. After landing, national context follows the selected Policy Atlas, Street map or Satellite appearance; weather does not switch that appearance. A soft ocean frame obscures neighbouring land. The zoom floor fits the full Maldives chain to the usable viewport rather than using a fixed zoom or tight longitude bounds that would crop the country on wide screens. After the opening, the map uses Mercator and restricts user panning to the national extent. The national background does not extend the local access model beyond Greater Malé. Explicit camera fits replace retained padding; point focus clears all four insets before applying its offset so the two camera workflows do not double-count panels. Closing weather preserves the camera; returning to Greater Malé is an explicit action.

## Failure behavior

Provider fetches have bounded timeouts and coalesce concurrent requests. An upstream failure does not block the planning map. Brief cached fallbacks keep their original observation/retrieval timestamps and are explicitly stale; expired observations are removed. Missing metrics remain unknown. Rate-limited feeds back off. Automatic refresh stops while the map page or browser is hidden.

## Verification

Live probes on 13 October 2026 returned aircraft from ADSB.lol and complete weather/marine samples for the earlier 259-node narrow Open-Meteo grid. An earlier production check returned all 259 wave samples but 209 wind samples after one provider request failed; the map correctly displayed partial coverage and retained empty values in the missing region. The replacement ocean-wide 240-node geometry has parser/cache tests. The anonymous Open Waters Maldives query returned a valid empty result; a separate covered-region probe confirmed real vessel positions and dimensions. The ship layer therefore supports actual observations but does not claim complete Maldives coverage. Optional AISStream requires a user-issued key and was not live-tested with a key.

The new current-weather service was live-probed on 13 October 2026: NOAA returned a VRMM observation valid at 09:00 UTC / 14:00 MVT, with 30°C, wind from 070° at 11 knots and light rain showers. The service retained the actual station timestamp and left unreported rainfall amounts and gusts empty. These values document that probe and are not fixed application defaults. Focused current-weather tests cover station selection, stale/future timestamps, coordinates, variable wind, missingness, model units and interval rain, request coalescing, fallback, cache expiry and rate limits.

The previous baseline passed all 826 tests across 87 files. Parser and cache tests cover coordinates, timestamps, units, missing dimensions, weather joins, failure recovery, rate limits and secret-safe errors. Weather tests additionally cover physical vector interpolation, exact grid corners, missing-hour gaps, Mercator texture positioning, cached-clock rebasing, six-hour client expiry, partial route sampling and terminal/calendar provenance. Nine camera tests cover responsive country fitting, invalid dimensions, excessive padding and constrained national panning. Current changes add a separate station/fallback test suite and update grid tests for the wider geometry.

Svelte checking reports zero errors or warnings; lint and the production build pass. The build retains the existing large-bundle advisory.

Historical production-browser checks covered the desktop viewport, 390 × 844 and 320 × 720 mobile layouts, the Earth opening and Malé landing, resizing during the active opening, skipping the intro and the disabled zoom-out button at national extent. Earlier feed checks covered vessel coverage/size legend, aircraft selection and a disconnected local API. Checks of continuous weather layers, forecast playback and the forecast dock belong to the previous interface; those features have been removed from the map Weather workflow.

The impact workflow has focused tests for observed versus model exposure, fresh/missing weather, island scope, selected-road closures, grouped rain delay, legal directional routing and saved-scenario recovery. The weather-only comparison and existing edit/hexagon suites passed 43 focused tests: prior proposal effects are excluded, missing journey evidence is separated from lost access, durations use population-weighted reachable pairs, and 2030 display allocations retain their population totals.

The completed impact redesign passed 865 unit tests across 90 files, Svelte checking with no errors or warnings, scoped ESLint and formatting checks, and the production build. Desktop browser checks at 1920 × 1080 and 1365 × 768 verified the current station report, rain colors and journey comparison, selected flood roads and red nearby cells, road inspection, clearing and undo, national weather icons, and preservation of the Street map appearance. Weather-open zoom controls were moved beside the sidebar and verified unobstructed. The final browser session reported no console errors. Test disruptions were removed after verification.
