# Backend replacement: feature audit

This is the historical audit of the supplied backend before the policy expansion. The six requested missing capability groups have since been implemented; see [policy-expansion.md](policy-expansion.md) for the current feature inventory, coverage and verification.

Audited on 14 October 2026 from implementation code and the supplied data artifacts. This document compares the application **before the revamp** with the backend supplied in `C:\Users\cena2\Downloads\backend\backend`. Documentation in the Downloads folder is useful context, but only implemented routes and service behavior count as support here.

The original application, including uncommitted edits and local data, is preserved at:

`D:\Projects\Personal\datathon-backup-20261014-124331`

The imported backend lives at `backend/` in this repository. Original `src/` references below refer to that backup; backend references refer to `backend/app/`.

## Main finding

The supplied backend is a working foundation for a **national island atlas, static accessibility screening, land and marine geometry routing, transport scenario edits, recommendations, and optional live vehicle positions**. It is not a replacement implementation of the original application's timetable-aware journey model, passenger forecasting, policy economics, or public-notice workflows.

In particular, its scenario endpoints report changes in **graph and feature counts**. They do not calculate how many residents gain access, how long journeys take, how access scores change, or what an intervention costs. Calling these endpoints cannot preserve those old outcomes without additional backend implementation.

Legend: **Supported** = implemented backend capability; **Partial** = related capability with a materially different contract; **Missing** = no corresponding implemented backend service/API. Browser-only presentation and storage features can be rebuilt independently, but that does not fill missing calculations.

## Implemented API surface

The inspected `app/main.py` registers these routers:

- Health: `GET /health` (a service-health response; no separate readiness endpoint is registered in the supplied code).
- National data: `GET /api/v1/islands`, `/islands/{id}`, `/islands/{id}/profile`, `/map/features`, `/national/summary`.
- Routing: `POST /api/v1/routing/land`, `/routing/marine`.
- Accessibility: `POST /api/v1/accessibility/score`, `GET /api/v1/accessibility/summary`.
- Scenarios: `POST /api/v1/simulation/run`, `/simulation/compare`.
- Recommendations: `POST /api/v1/recommendations` with `underserved_island`, `bus_stop`, `ferry_terminal`, `ferry_route`, `parking`, `mobility_hub`, `pedestrian`, or `airport_access`.
- Live data: `GET /api/v1/live/status`, `/live/snapshot`, `/live/stream`.

The scenario model supports `add_bus_stop`, `move_bus_stop`, `remove_bus_stop`, `add_ferry_terminal`, `move_ferry_terminal`, `disable_ferry_terminal`, `add_ferry_route`, `remove_ferry_route`, `change_ferry_route`, `add_parking`, `add_park_and_ride`, `add_mobility_hub`, `road_closure`, `pedestrian_connection`, `airport_access_improvement`, and `weather_disruption`.

Some methods exist only internally and should not be mistaken for API routes: `ScenarioSession.undo/redo/reset/clone`, facility mapping review repository methods, and FollowMe neighbor/ETA helpers. The application registers no account/authentication, database persistence, saved-project service, citizen-feedback API or public write interface for normalized source records.

The last supplied prewarm report was generated on 13 October 2026. Its source-refresh phase was skipped and used the last-known-good raw cache; artifact generation dates are not source observation dates. The original supplied national-summary artifact contains `accessibility_status: "not_calculated_in_phase_2"` although a completed default accessibility artifact is present. The imported backend now corrects that stale status in its runtime API response; the original supplied artifact is preserved.

The default accessibility model treats a mapped bus feature and airport as transport-presence indicators. Ferry access remains unverified unless explicitly enabled in scoring policy. Health/education distance may fall back to straight-line distance where a walk graph path is unavailable. Scores are policy-dependent screening indices; their `confidence` is a rule based on missing-data count, not a calibrated probability.

## Revamp interpretation

The replacement application should expose the backend's actual islands, source quality, static scores, shortest-distance routes, structural scenarios, screening recommendations and live feed status. Unsupported forecast and journey-economic workflows should be clearly marked as unavailable or removed from the replacement navigation. Old outputs should not be regenerated from unrelated graph counts or heuristic recommendation scores.

Old local proposal files remain recoverable in the backup. Browser saves are separate from filesystem files: the old `mobility-planning-scenario-v1` key is left untouched in the browser, while the new app uses `mobility-v2-scenario`. Browser storage is not included in the filesystem backup. Automatic migration would require explicit mappings between the old baseline/version IDs, stop/facility/service actions and the new national object IDs. There is no safe schema-only conversion for timetables, facility proposals, costs or return-journey assumptions.
