# Application audit — 16 October 2026

Four workers reviewed backend logic, frontend data lifecycles, map planning, and application integration. Confirmed defects were reproduced and repaired; the tables below distinguish product bugs from coverage limits.

## Confirmed bugs and fixes

| #   | Area                        | Before / reproduction                                                                                                                                                                           | After                                                                                                                                                           | Why it matters                                                                        |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1   | Saved map proposals         | A saved operation list containing `null` crashed the hydrated map with an internal error. Obsolete entries were trusted as current operations.                                                  | Validate restored entries, retain valid changes, preserve route packages atomically, and show a recovery warning for discarded changes.                         | An old or damaged local draft should not make the application unusable.               |
| 2   | Map keyboard handling       | Arm a school placement, switch to Analytics, then press Escape: the hidden map cancelled the placement. Both the map and page registered global handlers.                                       | Both handlers check that the map workspace is active; map controls also respect already-handled events.                                                         | Keyboard actions belong to the visible workspace.                                     |
| 3   | Clustered map icons         | Dynamic vessel and infrastructure sprites were added through an event that fired after MapLibre had collected the render response. First rendering could miss icons and log warnings.           | Resolve missing sprites with MapLibre's awaited image resolver.                                                                                                 | Ships and grouped places remain visible when they first appear.                       |
| 4   | Restored planning dates     | A stored value such as `2026-02-31` passed the format check and reached planning requests.                                                                                                      | Restore only real calendar dates; otherwise use the valid captured baseline date.                                                                               | Invalid local settings should recover before evaluation.                              |
| 5   | Fleet resources             | Save sat outside a form, so HTML bounds did not prevent negative/fractional vehicle counts, zero capacity, or invalid battery/charging values from entering the proposal.                       | A shared validator applies backend bounds before saving; rejected input leaves the saved draft unchanged and shows a readable error.                            | Users can correct inputs before a later evaluation fails.                             |
| 6   | Forecast source refresh     | Accepting sources elsewhere while Passenger outlook or Data & method was retained could leave the forecast or source inventory stale.                                                           | Subscribe to source invalidation, defer refresh while hidden, and preserve unapplied target-month edits. | 7   | Place provider status       | Change islands while the one-time provider status request is pending: scope cleanup aborted the only status request, leaving “Checking provider” indefinitely.                                  | Give provider status a component lifetime independent of island-specific requests.                                                                              | Changing the map scope cannot strand status loading.                                  |
| 8   | API error recovery          | Malformed HTTP 200 JSON on cacheable endpoints leaked raw parser errors.                                                                                                                        | Return the same readable `ApiError` as other reads; failed payloads are not cached and retry can succeed.                                                       | Temporary response corruption has a clear recovery path.                              |

| 12  | Chart units                 | Comparisons ignored the plural `units` column and accepted incompatible raw values.                                                                                                             | Recognize `unit` and `units`, rejecting incompatible raw comparison axes while allowing indexed comparisons.                                                    | Charts cannot silently imply compatible quantities.                                   |

## Verification

- Full backend suite: **738 passed**; Ruff lint and format checks passed.
- Frontend unit suite: **229 passed** across 19 files. Startup suite: **6 passed**.
- Browser verification: **142 checks passed across 14 suites**, with no recorded browser runtime errors. The final `npm run test:browser` run passed all seven main suites; the focused map suites were rerun after the mobile route fix.
- Production build passed. Svelte type checks reported **0 errors and 0 warnings**; frontend formatting and ESLint checks passed.
- Added regressions exercise invalid draft recovery, package integrity, inactive Escape, invalid dates, missing map sprites, fleet bounds, source invalidation, provider-status races, readable API errors, chart identity/units, complete sorted exports, and notice filtering.
- Updated browser harnesses to wait for completed asynchronous proposal imports and to open weather evidence through the current map-first controls. Returning through the Map & planning button intentionally resets the map to the capital view; hidden Escape is checked before that navigation reset.
- Browser checks use real backend responses. Delay/failure scenarios alter delivery timing or simulate a disconnected response; timetable acceptance runs against an isolated copied-data backend.
- Manual browser review covers analytics filters, analytics-to-map drill-down, route-point placement and cancellation, partial-route reset, Evidence navigation, and narrow-screen map/proposal layouts.
- PDF visual QA rendered and inspected all nine pages of the exported ferry proposal: cover, access charts, budgets, map, service tables, and evidence appendix. No clipped text, overlapping content, missing chart labels, or broken page numbering was found. Poppler emitted fallback-font warnings, with no visible missing glyphs in the rendered pages.
- Retired the obsolete places browser harness and pointed `npm run test:browser:places` at the maintained map-first suite. Updated its documentation and verified the public command.

## Scope and limits

The review includes analytics, passenger forecasts, source receipts, datasets and exports, map exploration, local and inter-island journeys, proposal placement and comparison, delivery resources, conditions/notices, places, navigation, caching, proxy forwarding, and startup ownership/build reuse. It does not certify upstream providers or remove existing data coverage limits. Live services may return partial or unavailable data; captured timetables remain dated snapshots. No environment values or credentials were changed or included in this report.
